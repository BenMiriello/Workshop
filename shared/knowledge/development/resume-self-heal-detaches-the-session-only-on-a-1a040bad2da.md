Change (2026-08-26, build_streaming.py): the failed-resume self-heal at the end of _commit_turn used to run `if is_error and meta['resume'] and meta['session_id']: clear_thread_session(...)`, detaching the thread's durable claude session on ANY turn error. That discarded the CLI's on-disk transcript on transient failures (a 529, an expired token, a dropped socket), forcing a lossy summary+tail rebuild on the next turn: context leaving before a compaction, which the model of record (docs/platform-redesign/chat-context-and-compaction-2026-08-25.md) forbids.

Now gated on `_resume_failure_is_session_fault(detail, produced_output)`: detach only on an explicit resume-miss signature (_RESUME_MISS_HINTS, e.g. 'No conversation found with session ID'), or on a startup failure that produced no output and carries no transient signature. Keep the session on a recognized transient (_looks_like_auth_failure or _TRANSIENT_HINTS: overload/rate-limit/429/529/network) or any failure after output had been produced. The no-output arm preserves the original anti-loop guard (a truly broken session is not resumed forever); session_alive still backstops a file that is genuinely missing. Test: backend/tests/test_resume_self_heal.py.

Open follow-up (NOT fixed here): the compaction adapter claims native_auto=True but the 2026-08-25 measurement found the CLI never auto-compacts in -p. If true, a durable resumed session grows unbounded until a window error, so the minimal Workshop fold must be what fires on the CLI path. Resolve before relying on 'the CLI shrinks its own window'.
