The interactive AskUserQuestion built-in is on a baseline `--disallowedTools` list for every tool-bearing chat turn (llm_router.BASELINE_DISALLOWED_TOOLS, applied in tool_flags for the narrow + full-agentic-with-selection paths and inline in build_streaming for the full-agentic-no-selection path). Reason: in a headless `claude -p` chat turn only the tool's PERMISSION chip renders; the question text and its options never surface as something the operator can answer, so approving it returns no answer and the model marches on choosing for the operator (observed 2026-08-17, three times). Do not re-enable it. For a structured choice, emit a ui-card; for an open question, ask in prose. The heavy alternative (durable suspend/resume keyed on the pending tool_use_id, using the jobs `awaiting_input` machine) is deliberately not built. Committed in a4833a1.
