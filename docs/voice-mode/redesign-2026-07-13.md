# Voice mode redesign, 2026-07-13

Status: PLAN (review pass over the 2026-07-12 inline reintegration; no code changed yet).
Scope: the whole STT/TTS/turn pipeline (`voiceSession.ts`, `voice.ts`, `useVoiceSession.ts`,
`voice_worker.py`, `routes/voice.py`) plus the inline chat UI (`Chat.tsx` voice wiring,
`VoiceSettings.tsx`, `components.css`). Supersedes nothing: `design.md` remains the v2
architecture record; this doc is the corrective redesign on top of it.

---

## 1. Diagnosis: what is actually wrong

Ranked. Each item is verified in code, not inferred.

### D1. Failures are invisible; several paths wedge with no feedback (severity: critical)

The operator's "usually fails to respond" is mostly this: the engine has an `error` field
and it is rendered NOWHERE. `vsnap.error`, `vsnap.queue`, `vsnap.lastTurnMs`,
`vsnap.sttProvider/ttsProvider`, and `vsnap.queuedSend` are all unused in `Chat.tsx`
(grep confirms zero references). They were rendered by the deleted `VoiceMode.tsx` page and
the reintegration dropped every one of them. Concretely:

- Mic permission denied on the server STT path: `start()` sets `error` and goes `idle`
  (`voiceSession.ts:252-254`), but `voiceOn` stays true and the orb's label fallthrough
  says "Listening" (`Chat.tsx:1298-1301`). The user sees a live-looking orb that will
  never hear anything.
- Server STT request fails mid-conversation: `transcribeBlob` errors are swallowed
  (`voiceSession.ts:395-397`), segments come up empty, and the utterance silently
  evaporates (`voiceSession.ts:406-411`). You spoke; nothing happened; no message, no error.
- Browser STT with permission denied: `recognizeOnce` rejects and the catch re-arms
  unconditionally (`voiceSession.ts:363`), an infinite retry loop.
- No client-side watchdog on `thinking`: a stalled SSE that never errors leaves the state
  machine in `thinking` forever (the server's 60s timeout covers most cases, but a build
  voice turn has a 900s ceiling with zero visible tool activity, see D5).
- `probeServer`/`detectCaps` fetch with no timeout (`voice.ts:55-63`): a hung backend
  leaves the session stuck in `connecting`.

### D2. The speculative-endpointing pipeline has real races and destructive side effects (severity: critical)

- **No state re-check after awaits in `onEagerPause`** (`voiceSession.ts:433-453`). It
  checks `state === "listening"` at entry, then awaits `cutSegment()` and
  `transcribeBlob()` (250-400ms each, worse under GPU contention). If the real endpoint
  fires during those awaits, `onSpeechEnd` runs with the eager segment's text still in
  flight: the final join misses it (turn answers a truncated utterance), or the empty-final
  path resets `segs` and the late eager text then lands in the fresh array and fires a
  HELD draft with the user already silent. A held draft with no endpoint coming never
  commits: mic listening, audio held, user waiting, nothing ever plays. This is a
  plausible direct cause of intermittent "no response".
- **`supersedeDraft` fires the full `finishSpeaking` machinery by accident**
  (`voiceSession.ts:488-502`): `speaker.stop()` synchronously invokes
  `onDone -> finishSpeaking` (`voice.ts:482-487` -> `voiceSession.ts:711-740`) while
  `held` is still true and `_interrupted` is true. Consequences: (a) the draft's never
  spoken reply is queued as a phantom "background thread" (`voiceSession.ts:722-729`),
  (b) `mic.startRecording()` is called mid-utterance (`voiceSession.ts:733-736`), which
  resets `chunks = []` and clips the audio of the sentence the user is currently speaking.
  So every superseded draft corrupts both the queue and the current utterance.
- **No correction marker on supersede.** `design.md` section 4 specifies a
  `[correction: my previous message was an incomplete fragment...]` prefix on the
  committed turn after a supersede. `cancel_turn` only sets `pending_note` for
  `reason == "barge"` (`voice_worker.py:457-462`). The model session silently accumulates
  fragment turns plus partial replies the user never heard, and the next reply can refer
  back to them ("as I was saying...").
- Barge-in clips the start of the user's interruption: nothing records during `speaking`,
  and recording only restarts after the 180ms sustain window plus `finishSpeaking`
  (`voice.ts:180-186`, `voiceSession.ts:733-736`), so the first word of "stop, actually..."
  is routinely lost.

### D3. The live controls are placebos (severity: high)

- `resolveProviders()` runs only inside `start()` (`voiceSession.ts:250`). `setPrefs`
  (`voiceSession.ts:233-242`) never re-resolves. So the composer's reply-mute button
  (`Chat.tsx:1371-1380`) and the Speech/Hearing engine choices in settings do NOTHING
  until voice is toggled off and on. The mute button flips its icon and keeps talking.
- The hook returns `prefs: prefsRef.current` (`useVoiceSession.ts:242`), a plain ref, and
  `updatePrefs` sets no state (`useVoiceSession.ts:231-240`). The controls only repaint
  because the 60fps mic-level emit happens to re-render Chat. With the mic muted (no level
  loop) the settings modal's toggles visually freeze.
- The debounced `putPrefs` persists only the LAST patch (`useVoiceSession.ts:236-237`):
  change Voice then Speed within 400ms and the Voice change is never saved.
- "How easily I cut in" (`barge_sensitivity`) actually drives `setSensitivity`, the
  GLOBAL VAD onset threshold (`voice.ts:121-124`, applied at `voiceSession.ts:235`), so
  the slider also changes normal utterance detection. Mislabeled control.
- `verbosity` is surfaced in settings but read by nothing on the backend
  (`_VOICE_SYSTEM` ignores it). Another placebo.

### D4. Rendering architecture: 60fps re-renders and the vanish-then-pop overlay (severity: high)

- `onLevel` emits a snapshot invalidation every animation frame while the mic runs
  (`voice.ts:175` -> `voiceSession.ts:262`). `useSyncExternalStore` then re-renders the
  ENTIRE Chat component, message log and markdown included, ~60 times per second for the
  whole voice session. Jank on mobile, battery burn, and it is what masks D3.
- The live overlay renders only during `thinking|speaking` (`Chat.tsx:1190`) and the
  refetch on finish is async (`Chat.tsx:481-492`): between the state flipping to
  `listening` and `getThread` landing, the just-finished exchange disappears from the log,
  then pops back. Every single turn flickers.
- The overlay shows `cleanForSpeech` text (markdown stripped, URLs replaced with "link",
  `voiceSession.ts:633`, `voice.ts:663-677`) while the persisted message is the raw text
  (`voice_worker.py:404-421`), so the settle also restyles the content. Combined with the
  gap above, every turn visibly jumps twice.

### D5. The reintegration silently amputated half the feature set (severity: medium)

Dead but still costing complexity: the background-thread queue (barge remainders
accumulate invisibly in `vsnap.queue`; `offerThread`/`dismissThread`/`speakLocal`/the
aside protocol are unreachable), the latency readout (`lastTurnMs`), the engine-truth
footer, the queued-send badge (`enter_interrupts=false` queues a send with zero
indication, and a second queued send silently overwrites the first,
`voiceSession.ts:536`). Voice BUILD turns are worse: tool events stream from the worker
(`voice_worker.py:248-254`) but the client ignores them (`useVoiceSession.ts:86-104`
handles only text/done/error), so a build-by-voice turn shows "Thinking..." for minutes;
and `_persist_turn` stores no segments meta, so the thread history of a voice build turn
has no tool record at all.

### D6. Composer/settings UX and platform gaps (severity: medium)

- Two adjacent mic glyphs with different meanings: the orb shows a `Mic` icon when
  listening/idle (`Chat.tsx:1292-1297`) right next to the mic-mute button's `Mic/MicOff`
  (`Chat.tsx:1361-1370`). This is exactly the "mismatched buttons" confusion the operator
  already flagged once.
- 14 controls in one flat settings sheet; essentials and one-time-tuning knobs undivided.
- No `aria-live` for voice state; state changes are conveyed only by icon/color.
- iOS Safari: `MediaRecorder` does not support `audio/webm`; `startRecording`
  (`voice.ts:219-228`) constructs it anyway and throws uncaught, so the server STT path
  (the auto pick on mobile web) crashes on iPhones.
- Autoplay policy: a held draft's audio is released by `setHeld(false)` outside any user
  gesture (`voiceSession.ts:482`); `a.play().catch(() => advance())` (`voice.ts:470`)
  swallows the block and silently marks sentences heard without playing them.
- First-turn `speakFiller("One moment.")` uses the browser voice while the reply plays in
  Kokoro (`voiceSession.ts:426,519`): two different voices in one turn, and with a warm
  worker (~1.25s) the filler overlaps the real reply.
- Backend hygiene: `TURNS` is never pruned (`voice_worker.py:137`), growing until restart.

## 2. Target design

### Mental model (the whole thing, four sentences)

Voice is a lane on the SAME conversation, not a place. The orb is the one instrument: it
shows whose turn it is, and tapping it always means "cut to me" (interrupt speech, or send
what I've said now). Esc stops speech; Enter always sends and always interrupts. Typing
means "wait for me"; talking over the assistant means "stop".

That removes two prefs (`enter_interrupts` becomes fixed behavior; the queued-send path is
deleted with it) and makes every interrupt affordance converge on the same verb.

### Zero-config default experience

Toggle voice on: mic goes hot, replies are spoken, the status line under the log says what
is happening at all times ("Listening", "Heard: <partial>", "Thinking", "Speaking, Esc to
stop", or a red error with Retry). Pause 0.9s and it answers, fast (eager STT keeps
speculation, fixed after Phase 1). Talk over it and it stops within a sentence and
remembers exactly what you heard. Type mid-conversation and it waits, then speaks its
answer. No settings visit required, ever.

### Decisions (cuts and changes, stated plainly)

1. **CUT the background-thread queue entirely** (queue, `offerThread`, `dismissThread`,
   `speakLocal`, the `⟦aside:⟧` protocol). It has been dead UI since the reintegration,
   its only live effect today is the phantom-entry bug (D2), and its job is already done
   better by the transcript: the full reply is persisted and visible in the bubble, with
   `meta.heard` recording where you stopped listening, and the worker gets the
   interruption note. If "offer me what I missed" ever comes back, it comes back as a
   model behavior (it can see the note), not client machinery.
2. **CUT prefs from the UI**: `enter_interrupts` (fixed on), `typing_hold_ms` (fixed
   3000), `eager_silence_ms` (fixed 400), `verbosity` (unwired placebo). Backend keys stay
   accepted for compat; the UI stops showing them.
3. **Keep speculative endpointing, fixed, default on.** The races are fixable with a turn
   epoch (below); the latency win (~0.9-1.5s) is the headline feature. If Phase 1 slips,
   the fallback is flipping `eager_endpoint` default to off, one line.
4. **Keep typed-in-voice routing through the voice worker** (warm, same thread, spoken
   reply). The model is: voice mode means the conversation is spoken; typing is just
   another way to say something. Want text-style answers, exit voice mode. No per-message
   modality switch.
5. **One mic glyph.** The orb never shows `Mic`; it uses `AudioLines` (listening, with the
   level halo), `Loader` (thinking), `Square` (speaking, the stop affordance),
   `AlertTriangle` tint (error/idle-unexpectedly). The mute button remains the only Mic
   icon.
6. **A one-line status strip** replaces the ghost line and becomes the single voice status
   surface: state, live partial transcript, errors with Retry, all `aria-live="polite"`.
7. **Level animation leaves React.** The orb halo is driven by a ref writing `--vlevel`
   directly on the element; the snapshot no longer carries `level` and emits only on
   discrete changes.
8. **Overlay settles instead of vanishing**: it stays rendered until the refetch has
   landed and contains the turn, then swaps once.

Six 2.1rem buttons on one row fits 390px (context meter already hides in voice mode). The
voice cluster (orb..gear) gets a subtle shared background pill so it reads as one group,

### Orchestration fixes (engine level)

- **Turn epoch**: `VoiceSession` gets a monotonically increasing `epoch`, bumped by every
  endpoint, supersede, barge, submitText, and stop. Every async continuation
  (`onEagerPause` post-await, `transcribeBlob` results, speaker `onDone`, reply handlers)
  captures the epoch at start and no-ops if it no longer matches. This one mechanism
  closes every race in D2 without restructuring the machine.
- **Detached speaker teardown**: `Speaker` gains `detach()` (null the event sink before
  `stop()`), used by `supersedeDraft` and `stop()` so `finishSpeaking` only ever runs for
  a turn that actually spoke.
- **Continuous recorder discipline**: the recorder never restarts mid-utterance. On
  barge, recording starts at bargeMode arm (speaking start) and the pre-barge segment is
  cut and discarded at barge confirm, so only the ~180ms sustain window is lost instead of
  sustain + restart latency, and supersede never touches the recorder at all.
- **Client watchdog**: 70s (conversational) timer in `thinking`; on trip: visible error in
  the status strip, one automatic retry via the blocking fallback, and a short spoken
  notice when `speak_replies` is on ("That one failed, retrying").
- **Live prefs**: `setPrefs` re-resolves providers. Mute-replies mid-speech stops the
  speaker and marks the remainder heard; unmute applies from the next turn. Engine changes
  apply from the next turn. Prefs become React state in the hook.
- **Worker session hygiene** (backend): supersede sets a `pending_note`
  (`[correction: my previous message was an incomplete fragment of the next one and your
  reply was never spoken; answer the full message fresh.]`); tool events are persisted as
  segments meta so voice build turns keep their history; completed `TURNS` entries pruned
  after 10 minutes.

## 3. Implementation plan (phased, dependency-ordered)

Each phase is sized for one implementer subagent and leaves the system working.
Verifiability legend: **[FE-hot]** frontend only, hot-reload, `cd frontend && npx tsc
--noEmit` + `bash scripts/check_design.sh` (+ `vite build`); **[BE-restart]** backend,
needs `scripts/restart_backend.sh`; **[LIVE-mic]** final confirmation needs the operator's
session and a real microphone (see section 4).

### Phase 1: engine correctness [FE-hot] + [LIVE-mic]

Files: `frontend/src/lib/voiceSession.ts`, `frontend/src/lib/voice.ts`.

1. Add the turn epoch; guard `onEagerPause` (re-check `state === "listening"`, `capturing`,
   and epoch after each await), `onSpeechEnd`, reply handlers, and speaker events.
2. Add `Speaker.detach()` to all three speakers; use it in `supersedeDraft` and
   `stop()`. Delete the queue-on-supersede and recorder-restart side effects (D2 bullet 2).
3. Delete the background-thread queue: `queue`, `QueuedThread`, `offerThread`,
   `dismissThread`, `speakLocal`, `extractAsides`, `ASIDE_RE`; `finishSpeaking` keeps only
   heard accounting + the cancel report.
4. Client watchdog in `thinking` (70s), one retry, spoken failure notice; remove the
   mixed-voice `speakFiller` on turn 1 (the warm worker made it obsolete; keep it only for
   the genuinely cold `connecting` path, or delete outright: DELETE, simplest).
5. Browser STT: stop the infinite retry (cap 3 consecutive empty/failed re-arms; on
   `not-allowed` set a permanent error, no re-arm).
6. `start()` mic failure and any fatal error: set `error`, stay `idle`, and emit; expose
   `snapshot.fatal` so the UI can drop `voiceOn` (wired in Phase 3).
7. Fix `Enter` semantics: always interrupt + send; delete `pendingSend`/`queuedSend`.

Acceptance: tsc + check_design pass; a written walkthrough of the three D2 race scripts
against the new code (epoch traces); operator script items 1-5 (section 4).

### Phase 2: live prefs and provider resolution [FE-hot]

Files: `frontend/src/lib/useVoiceSession.ts`, `frontend/src/lib/voiceSession.ts`,
`frontend/src/lib/voiceApi.ts`.

1. Hook holds prefs in `useState`; `updatePrefs` sets state, pushes to the session, and
   accumulates a pending patch object that the 400ms debounce flushes whole (fixes the
   dropped-patch bug).
2. `setPrefs` re-resolves providers when caps are known: `speak_replies` off mid-speech
   stops (detached) the speaker and marks remaining sentences heard; `speak_replies` on
   takes effect next turn; `tts_provider`/`stt_provider` changes re-resolve for the next
   turn; `mic_enabled` keeps its existing live path.
3. One caps truth: session exposes `snapshot.caps`; Chat's separate `detectCaps` state is
   removed and `VoiceSettings` reads the snapshot (with a mount probe only when the
   session is idle).

Acceptance: tsc; with voice on, tapping the reply-mute button mid-reply silences within
the current sentence and the icon reflects it with the mic muted too (no 60fps crutch,
requires Phase 3's emit discipline or a temporary state mirror, note in PR); settings
sliders move and persist across reload (curl `/api/voice/prefs` to confirm both fields of
a rapid two-field change landed).

### Phase 3: chat UI, status strip, orb, overlay settle [FE-hot]

Files: `frontend/src/components/Chat.tsx`, `frontend/src/styles/components.css`.

1. Status strip above the composer (replaces `.chat-voice-ghost`): renders state word,
   live partial, or `snapshot.error` with a Retry button; `role="status"
   aria-live="polite"`. Auto-exit voice (`setVoiceOn(false)`) plus strip error on
   `snapshot.fatal`.
2. Orb glyphs per section 2 decision 5 (no `Mic` icon on the orb); voice cluster grouping
   pill; verify 1440/1024/768/390 (CSS harness, same approach as the 2026-07-12 pass).
3. Level out of React: snapshot drops `level`; session gains `onLevel` callback; Chat sets
   `--vlevel` via a ref. Emit only on discrete changes (state, sentences, partial, error,
   prefs-relevant flags).
4. Overlay settle: on turn finish, keep the overlay's user+assistant bubbles rendered from
   a local `settling` snapshot until the `getThread` response containing the new messages
   has been applied, then swap once. No frame where the exchange is absent.
5. Delete dead wiring: `queuedSend`, queue references, `enter_interrupts` UI implications.

Acceptance: tsc + check_design + `vite build`; CSS harness screenshots at the four widths;
React DevTools (or a render-count probe) shows Chat NOT re-rendering at frame rate while
listening; overlay settle verified live by the operator (script item 6).

### Phase 4: settings rework [FE-hot, one BE default touch]

Files: `frontend/src/components/VoiceSettings.tsx`, `frontend/src/lib/voiceSession.ts`
(DEFAULT_PREFS), `backend/routes/voice.py` (_PREFS_DEFAULTS comment only, keys stay).

1. Regroup per the sketch: 4 essentials + collapsed Advanced (a small `details`-style
   disclosure, add a `.ws-` rule; keep the shared Modal).
2. Remove `enter_interrupts`, `typing_hold_ms`, `eager_silence_ms`, `verbosity` controls.
   Rename "Think during pauses" to "Fast responses", "Let me talk over you" to "Talk over
   me to interrupt", "How easily I cut in" to "Mic sensitivity" with the honest hint.
3. Fix the eager/endpoint clamp so no stored value can go below its slider min.

Acceptance: tsc + check_design; modal fits and scrolls at 390px and short-viewport
(previous `.ws-modal` harness); prefs file after a save contains no orphaned UI-removed
keys being reintroduced.

### Phase 5: backend worker fixes [BE-restart]

Files: `backend/services/voice_worker.py`.

1. `cancel_turn(reason="superseded")` sets the correction `pending_note` (D2 bullet 3).
2. `_persist_turn` includes tool events as `meta.segments` (same shape the build chat
   stores) so voice build turns keep their tool history; keep `meta.voice` and
   `meta.heard`.
3. Prune completed `TURNS` older than 10 minutes (piggyback on `_reaper`).
4. Optional, small: title the auto-created voice thread from the first utterance's first
   40 chars instead of the permanent "Voice".

Acceptance: backend restart; direct worker-layer exercise per the memory note
(`ownership.set_current_owner(1)`, start a turn, cancel superseded, start a second turn,
assert the second wire message carries the correction prefix; assert TURNS pruning;
inspect a persisted build turn's meta).

### Phase 6: platform hardening [FE-hot] + [LIVE-device]

Files: `frontend/src/lib/voice.ts`, `frontend/src/components/Chat.tsx` (one call).

1. MediaRecorder mime negotiation: first supported of `audio/webm;codecs=opus`,
   `audio/webm`, `audio/mp4;codecs=mp4a.40.2`, `audio/mp4`; blob filename/extension to
   match (whisper handles m4a). Wrap `startRecording` in try/catch feeding
   `snapshot.error`.
2. `unlockAudio()` called from the voice toggle click: create/resume the shared
   AudioContext and prime one silent `Audio` play so held-draft releases are not blocked
   by autoplay policy; on a blocked `play()`, surface a status-strip hint ("tap to enable
   audio") instead of silently skipping sentences.
3. `probeServer` gets `AbortSignal.timeout(1500)`; `connecting` can no longer hang.
4. Barge pre-roll: start recording at bargeMode arm; cut-and-discard at barge confirm
   (keeps the recorder hot, loses only the sustain window).

Acceptance: tsc; desktop live check; iPhone Safari check is operator-gated (mobile memory
note: Expo shell has the native seam, but mobile WEB is the target here).

Dependencies: 1 -> 2 -> 3 -> 4 (frontend chain, each builds on the previous); 5 is
independent (can run parallel to 2-4); 6 last (touches the same files as 1, keep serial
after 1).

## 4. Risks and what cannot be verified headless

- **Login wall**: product-auth (httpOnly cookie, no localStorage token) blocks headless
  Playwright from the authed chat. All UI phases are verified by `tsc`, `check_design.sh`,
  `vite build`, and the standalone CSS harness against the real stylesheets (the method
  that validated the 2026-07-12 modal fix). No headless run can exercise
  mic -> overlay -> refetch.
- **Runtime audio needs the operator.** A 10-minute acceptance script to hand over after
  Phases 1-3 land: (1) deny mic permission, toggle voice: red status-strip error, voice
  exits, no fake "Listening"; (2) speak with a deliberate mid-sentence pause: exactly one
  reply, answering the whole utterance, no dead-air wedge across 10 tries; (3) barge in
  mid-reply: audio stops within a sentence, next reply knows where it was cut, the first
  word of your interruption is in the transcript; (4) kill the backend mid-conversation:
  spoken + visible failure within ~70s, Retry works after restart; (5) tap reply-mute
  mid-reply: silence now, captions continue; (6) watch three consecutive turns settle into
  the log with zero flicker; (7) type a message while it speaks: playback unaffected,
  Enter stops it and sends.
- **Worker-layer backend checks** are fully verifiable without the UI
  (`ownership.set_current_owner(1)` REPL path already proven on 2026-07-11).
- **Race fixes are argued, not unit-proven**: the repo has no frontend test harness, and
  adding one is out of scope here. Mitigation: the epoch mechanism is small enough to
  audit exhaustively in review, and the operator script items 2-3 hit the two worst races
  directly.
- **Echo on barge pre-roll** (Phase 6.4): with weak AEC the discarded pre-segment is the
  safety valve; if transcripts start containing the assistant's own words, revert 6.4
  alone (it is isolated).
- **Speculation cost**: keep the 2-fires cap; if the operator observes off-topic replies
  referencing unspoken drafts after Phase 5's correction marker, flip `eager_endpoint`
  default off (one line in two DEFAULTS) rather than iterating on prompt wording.
