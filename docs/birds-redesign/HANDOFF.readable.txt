Part 0
Two ideas govern everything
Every page and every chart in this document follows these two principles. They are the reason for the specific encodings that follow.
Idea 1
Presence over chatter
A bird that vocalizes constantly is not more significant than a quiet bird that's reliably around — raw detection counts over-weight the talkers and create false signals. The headline measure everywhere is presence = the number of 15-minute windows a species was detected in (≥1 detection counts once; no bonus for volume). Raw detections stay available, never dominant.
Idea 2
One question per surface
Each page and each chart answers a single thing fast; everything else is layered or one tap away, never stacked on top. Home is settled truth, Birds is review, Recent is presence, each chart has one reading.
Constant
One app, two chromes
A single responsive application: a left sidebar on web, top-bar + bottom tabs on mobile. A persistent Location · Device · Time scope applies on every page. Keep the existing component library, data layer and routing — this ports structure, encoding and behavior onto the real codebase.

1.3 — Global scope
Location · Device · Time, everywhere
A single persistent scope replaces all per-page and per-bird pickers. It applies on every content page — including bird detail. Pickers render as a bottom sheet on mobile, a centered modal on web.
Default scope opens to the home location + its always-on device ( Yard · Yard Mic ) so the live feed and "who's here now" are present immediately — never an ambiguous "all devices".
Time windows the analytical pages (Recent uses 15m / 1h / Today; Activity and Forecast use the longer ranges).
Changing any scope dimension repoints every surface at once, including the Aviary and the live histogram.
1.4 — The pages
What each surface is for
Every page answers one question. Decisions below are final.
[svg] Home
The settled truth for the current scope: Live card → Recent → Activity → Forecast peek → Top birds → at-a-glance stats. Confirmed-only; no status filter on Home, so nothing silently reshapes above the fold.
Recent
Presence, not chirp-count. Each species appears once , newest first, with its latest time + how many 15-min windows it appeared in. Windowed 15m / 1h / Today, paginated 10/page. Raw per-detection lists live on the bird page.
[svg] Birds
The review surface. Confirmed / Suggested / Rejected segmented at top, default Confirmed, counts match the list. The only place place-level status review happens.
Bird detail
Uses the global scope (no local pickers). Confirmed activity chart; detection rows collapse to essentials, expand to per-event status + device; per-bird recording mode (Default / Always / Never) .
[svg] Forecast
Species-led: the week chart + per-day detail + weather/light context. (Charts in Part 2.)
[svg] Atlas
Embedding map for labeling call clusters: Overview (yard colored by species) ↔ By-species (one bird's calls split into groups you listen to and name; new calls auto-join the nearest group ), plus zoom controls — and the new soundscape insight views. (Charts in Part 2.)
Recordings
Storage meter + budget + per-clip pin/delete.
Settings
Account; detection accuracy — min confidence, location-filter strictness, new-species confirmation count, re-apply to past; recording & Atlas budgets; non-bird display filter.
Locations & Devices
Minimal inline-edit lists (rename / address / set home / mode / share / remove). No per-location or per-device dashboards — viewing one = selecting it in the global scope. Yard Mic is flagged always-on (home device + default scope).
1.5 — Watch out
Placeholders in the prototype — don't regress the real app to match
Live histogram (Home live card): the structure prototype's generic spectrogram is a crude stand-in and worse than what exists. Keep the real production histogram (slides left over time, per-species icon riding each detection). Adopt only the container changes: a Listen control + a single pulsing "Live" indicator inside the live-card header , and remove the duplicate top-bar recording pill + top-bar Listen button — one recording affordance, not two.
Atlas map: the prototype's scatter of dots is fake — keep the real UMAP embedding; adopt the organization only.
Forecast copy/numbers & bird photos: placeholders; wire to real model output / media.
Diversity = Shannon H in production. The live charts in Part 2 use species-count-per-hour as a readable stand-in; the production activity/forecast charts should compute diversity as Shannon H . Also keep the real chart engine's All-days ↔ specific-day calendar scope , bar drill-down (tap a day → that day's hours), and maxBarSize so 1–2-bar charts don't balloon. The single-bird activity chart omits diversity (a multi-species measure, meaningless for one bird).
Part 2
Charts & data-viz — live
Every decided chart, rendered and interactive right here — toggle the overlays, flip presence vs. detections. Below each is the encoding spec. Global rules: Lucide icons only · smoothed trend lines with no point dots · every series on a labeled, color-matched axis · plain labels ("Temperature" not "Weather", "species" not "spp") · the day/night sky backdrop kept but always paired with labeled Sunrise/Sunset markers · descriptive copy, never prescriptive · forecasts drawn as a range .

2.6 — Implementation
How to build the charts
These were prototyped as hand-built SVG to pin down encoding. In production, reuse the app's chart stack ( recharts via ui.tsx 's CHART_SERIES / ChartTooltip ) where it cleanly expresses the spec; drop to custom SVG only for the radial / heatmap / scatter / novelty forms recharts handles poorly.
Pull colors from ui.tsx tokens — don't introduce new hues. Temperature uses the existing warm/orange token.
Keep all charts responsive (viewBox + preserveAspectRatio for custom SVG; ResponsiveContainer for recharts).
Respect prefers-reduced-motion : the day-over-day toggle animation reduces to an instant swap.
Part 3
The Aviary — an ambient lens on the live feed
The Aviary shows who's in the yard right now — each species heard in the rolling last 15 minutes flies in, pecks and hops while it keeps calling, lifts off when it goes quiet. It reads the same live data as the histogram , so it lives with the live card — surfaced as its expanded, cast-ready view, not as a fifth nav item.

How it behaves
01
Same data as the live card Driven by the rolling-15-min present-species set from the live source — no new data, just a second representation.
02
Scope-coupled Requires a live (always-on) device in scope, like the histogram. Default Yard · Yard Mic makes it always available; changing Location/Device repoints it.
03
Quiet-yard empty state Heard nothing in 15 min? A calm empty yard with a "listening…" note — a better idle than a flat-lined histogram.
04
Mobile = fullscreen takeover Opens from the live card, not a bottom tab. Side panel ("in the yard now" + controls) drops under the scene below 820px.
🛠
The engine is already built — reuse it. aviary-voxel.js (renderer + species library) and aviary.js (scene engine + window.Aviary API) are production-ready. Turn off the demo spawner with Aviary.simulate(false) and feed live data with Aviary.setPresent([...ids]) (the rolling-15-min present set; the engine reconciles birds in and out). Port only the surrounding chrome — don't rebuild the renderer or bird models.
✎
Naming. "Aviary" / "Live Aviary" reads well as "your birds, live" and needs no nav label of its own. If a more literal name is ever wanted, "The Yard" / "Live Yard" maps directly to the scene.

Build order & handoff notes
One path through all three strands, plus the corrections to carry from earlier rounds.
4.1 — Sequencing
Build order
Responsive shell Sidebar (web) / top-bar + tabs (mobile); wire the persistent Location · Device · Time scope to existing state/query params.
Home + live card Reorganize the dashboard; integrate the real histogram (Listen + Live inside, drop top-bar duplicates); add the Histogram ⇄ Aviary toggle + expand.
Recent (presence) 15-min-window collapse, latest-time sort, pagination.
Birds review + bird detail Status segmented at top (Confirmed default); global scope; expandable detection rows; per-bird recording mode.
Charts Times-of-day (no dots), day-over-day presence toggle, week "I"-range, day-shape band — over real model output.
Atlas Keep the embedding map for labeling; add the three soundscape insight views.
Aviary Port chrome around the reused engine; wire setPresent to the live source; fullscreen/cast + quiet-yard state.
Recordings, Settings, Locations/Devices Minimal inline-edit lists; no per-item dashboards.
