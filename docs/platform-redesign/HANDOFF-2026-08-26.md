## 1. What this system is trying to become

Workshop is a production web app. The redesign has one goal: work moves from a
conversation to a ticket to an agent that executes it and reports back, without
the operator managing the handoffs, and with context shared across chats so
nothing has to be re-explained.

Most of that exists. The parts that do not are named in section 4.

## 3. State of the system, briefly

**The autonomous loop is built and turned off on purpose.** Every piece exists:
the resident sweep (`queue_runner.sh`), the reconciler that keeps a runner per
armed scope (`work_driver.py`), readiness filtering, the per-scope execution
setting, bwrap confinement, the reviewer gate. The operator turned it off because
it works but does not work *correctly*. Section 4 names what "not correctly"
means, because that is the first track of work.

**Chat, tickets, memory, tools, files and the shell are built and in use.**
Confinement is live on every agent-spawning path. Tickets live in Postgres for
relational scopes.

**Usage accounting is broken in a way that blocks the limits work.** The ledger
has one column called `tokens` filled by three writers in three different units.
Nothing that reads it is trustworthy.

**App separation has not started.** Seven apps live inside the platform tree, and
no platform source file may name a specific app, which is measured by a gate and
currently violated in about a dozen places.

## 4. Where to start

Three tracks. They are independent, so they can run in parallel, but within a
track the order matters. Ticket ids are the first 8 characters; the store holds
the full id.

### Track 1: make the loop correct, so it can be turned back on

This is the highest-value track, because it is the reason the operator disarmed
the loop, and nothing downstream of it is testable while it is off.

The defects, all measured rather than suspected:

1. `ccd78488` **The test suite writes into the real usage ledger.** 4,208 of
   5,040 rows are test writes. Do this first regardless of track: it is small, it
   is corrupting the data every other measurement rests on, and it is a
   correctness bug in its own right (tests mutate operator state).
2. `0fb57b31` **`reclaim` does not advance the claim fence.** The docstring says a
   zombie worker is fenced; leaving the token intact means the zombie's token
   still matches, so a crashed worker's late write of `done` is accepted in the
   window between reclaim and re-claim. Carries a reproduction.
3. `e9a313c3` **An empty claim token** is treated as a match.
4. `4c59ee01` **A displaced worker continues best-effort** instead of stopping. It
   needs an exit code and allocates none; `70860d58` independently claims 8, so
   settle that collision when you take either.

Also in this track and worth knowing before you touch the gates: the `touches`
check runs post-hoc on the committed git diff, so on a shared checkout another
agent's commits land inside the worker's diff and the gate blames the worker. It
parked four tickets whose work was complete and in HEAD. Filed as `5d557e2a`.

When these land, the loop can be armed again. Do not arm it yourself; that is the
operator's call and he has already made it once.

### Track 2: fix what counts tokens, then the limits on top

Every limit, cap and cost figure rests on this, and none of it can be trusted
until it lands. In order:

1. `189b9e0e` `token_usage.py`, one module that parses a vendor usage block into
   named quantities. Nothing else re-derives a token count from a usage dict.
2. `c0bac5ad` The ledger row stores the four **components** (input, output,
   cache_read, cache_creation), not a single total. This is the decision that is
   expensive to retrofit and cheap now.
3. `16625867` Derive dollars from those components through a versioned price
   table keyed by `effective_from`.
4. `ea6f0c1a` Move all four writers onto it. `b83e417a` marks the existing 6.5
   billion tokens of history as v1 and never rescales it.

Then the limits themselves, which are designed and not built:
[limiting-usage-2026-08-24.md](limiting-usage-2026-08-24.md). Its final section
carries the operator's rulings: the monthly cap governs **autonomous work only**,
chat is never capped or warned, the default is a quarter of the plan price, the
plan is a setting that starts unset and is never inferred, and a provider that
says a usage limit was hit is recorded and not retried until the next window.

### Track 3: app separation

The largest body of work, 23 tickets, and independent of the other two. Start:

1. `84028d47` stand up `apps/` (unblocks the whole seven-app chain)
2. `2c13ef89` get app CSS out of the kit
3. `df91b7c4` name the ten disguised app modules
4. `d65244c4` extract health, which is the rehearsal the other six queue behind

Order is by dependency, not by CSS debt: extracting a provider first degrades the
live instance immediately, while CSS debt is recoverable effort. Plan:
[stage-7-extraction-plan-2026-08-24.md](stage-7-extraction-plan-2026-08-24.md).

The styling rule is settled and is not a question: the `@workshop/ui` kit is the
shared styling package, intended to be publishable to public npm, and app-used
classes that are not yet in it get consolidated **into** it. It is already
standalone-publishable today, verified. See ADR 0029.

## 5. What will trip you up

These are the traps that have actually cost work here. Read this section before
you trust any document.

**A doc's own claim about what shipped is not evidence.** Several current-looking
docs assert things that landed later or never. Two stale comments found on
2026-08-25 had each cost real work: one hid a live bug, the other deferred a fix
nobody needed to defer. Check the tree.

**The worst offenders, named:**

- [work-loop-core-design-2026-08-21.md](work-loop-core-design-2026-08-21.md) has
  two false central facts, no banner, and is the named core loop doc. It says the
  worker runs with no permission mode and has never written a file unattended;
  both are false.
- [HANDOFF-app-platform-and-github-2026-08-20.md](HANDOFF-app-platform-and-github-2026-08-20.md)
  is where `CLAUDE.md` sends agents for the app work, and its counts and its
  next-stage are both wrong.
- `work_review.py`'s docstring defers half its work to "the lease refactor (B3)".
  B3 shipped eight hours after that paragraph was written and the paragraph was
  never edited. Tickets `791f334e` and `e48268d0` give opposite instructions
  because of it.

**Live contradictions between current docs.** Thirteen are catalogued in the doc
index with quotes. The ones that will bite an implementer:

- Learnings as a `kind` versus a `reach`: two docs rule opposite ways and open
  ticket `81198145` builds the losing side. Its dependency is also cancelled.
- "Nothing queues. A queued turn is a refusal that lies" versus the pause-and-
  resume work: urgent ticket `70860d58` builds against a document that forbids it.
- The limit unit was contested between tokens and money. **That one is settled as
  of 2026-08-25: dollars, derived from components.** Ignore the older halves.

**Broken ticket dependencies**, which make a ticket look blocked forever or run
against a false premise: `81198145` depends on a cancelled ticket, `1638d7f9`
depends on a parked one and stalls the whole chat-storage chain, `29d24fb1` names
a nonexistent ticket, `b3f900d0` is missing the edge to the loader it needs,
`d4876c7c` targets a file deleted in `505f5907`, and seven more carry
already-done dependencies that read as open blockers.

**Twenty-five knowledge notes are now wrong**, listed in the knowledge index.
A stale note is worse than a missing one because search returns it as fact. The
worst: notes claiming the autonomy loop is dormant and cannot write a file, a
note saying there are five color palettes when there are eight, and two notes on
chat modes that contradict each other and both miss the third mode.

**Twelve false learnings were archived on 2026-08-26.** They were the
auto-generated "the direct approach is not converging" shape, injected into every
agent's prompt, naming work that had already landed. They were produced by gates
that were themselves broken. If you see that shape reappear, check whether the
gate is wrong before believing it.

## 6. Rules that are not optional

- **Run `bash scripts/apply.sh` when you finish editing.** It is the only current
  source on applying a change; [applying-changes.md](../applying-changes.md) has
  the detail. Restart and rebuild instructions in dated handoff docs are
  historical and wrong, and ten files still carry them.
- **Do not typecheck with `npx tsc`.** It resolves a deprecated stub that prints
  a message and exits 0. Use `npm run typecheck` from the repo root. Six docs
  still tell you to do it the broken way.
- **A screenshot is the only proof a screen is right.** `bash scripts/shoot.sh`
  loads the built app in a real browser at a phone frame.
  [previewing-an-app.md](../previewing-an-app.md). Typecheck, design check and
  1,600 tests have all passed green over screens that were plainly broken.
- **Write a ticket for two readers**, the worker and the operator on a phone
  weeks later. [ticket-writing.md](../ticket-writing.md).
- **No platform source file may name a specific app.** Gated by
  `scripts/check_no_app_names.py`; the counts may only go down.
- **Do not add multi-tenant guardrails.** Single operator. No allowlists, audit
  journals, or confirmation prompts beyond what one user needs.
- **Do not invent vocabulary.** Use the standard term or an existing field. Two
  inventions were rejected on 2026-08-25 and both reversals cost the designs
  nothing, which is the evidence they were never load-bearing.
- **Do not solve a problem by adding explanatory text.** State a fact once. An
  estimate gets one short note beside the totals in Settings, not a caveat on
  every figure.

## 7. What the operator still owns

Nothing in the current design documents is waiting on him. The open decisions
from earlier passes were answered on 2026-08-25 and folded into the docs that
raised them.

What remains his by nature, and no agent should file or attempt:

- **Arming the loop.** He disarmed it deliberately.
- **The 14 SEC tickets**, which need root or the host. Two of them (`77b22987`,
  `7f8f22d7`) are documentation only and an agent can do those.
- **Publishing.** `git push` to main is blocked by design; commit locally.
