## 0. The one-paragraph version

The autonomous loop had not completed a task since 2026-07-18, and the cause was
not the worker: three whole-tree gates measured the tree's total debt against a
static pin, so every run was rejected for debt it inherited. That is fixed and
proven today. Recall was never broken either; it was measured working at rank 1.
The real memory defect is smaller and more embarrassing than "search is broken":
there is one store wearing three names, a second store that exists only to be
pasted into prompts, and no way for the operator to see or prune either. The
provider and credential work the operator asked for is largely DESIGNED AND
BUILT already, and has no routes and no UI, which is this repo's signature
failure. So the next work is mostly connection, deletion and naming, not
invention.

## 1. What was wrong, measured

### 1.1 The loop (fixed today)

`.runtime/jobs.jsonl` records 2,066 loop jobs since 2026-07-18, every one with
`tasks_done: 0`. The worker was fine: it claimed tickets, did the work and
committed. `scripts/reviewer.sh` then rejected it, because
`check_no_app_names.py`, `check_module_layout.py` and `check_no_hardcoding.sh`
each measured the WHOLE tree against a pinned baseline. Once the tree's debt
drifted past the pin, from any source including concurrent agents and the
operator, every subsequent run failed regardless of what it changed. The worker
retried, collected the same rejection, tripped the no-progress thrash guard at
`scripts/ralph.sh:1128` and exited 6.

Nine reviewer-approved commits were stranded on locked `wt/development/*`
branches, and `changes.list_changes()` returned 0, so the entire change-review
apparatus had never processed a single record.

THE PRINCIPLE APPLIED: a run is judged on whether IT made a metric worse, not on
the absolute value of debt it inherited. The pinned baseline still governs
direction over time, so the ratchet is intact and no baseline was raised. This is
the same defect family as the `touches` gate blaming a worker for another agent's
commits, and the same family as billing a sweep to the basename of its directory:
**an identity or a responsibility derived from whole-tree state rather than from
the actor.** Expect it again. Four more gates carry it latently and are listed in
section 5.

### 1.2 Memory

Recall works. Measured today from a `development` chat, "is an app the same thing
as a project" returns `app-is-the-entity-2026-08-20.md` at rank 1, score 0.787.
The index holds 12,691 chunks. The embedding model is a local in-process ONNX
model, not the GPU: `BAAI/bge-small-en-v1.5`, 384-d, ~32MB int8, via fastembed,
moved off Ollama on 2026-08-20.

What is actually wrong:

- **One object, three names.** Backend `knowledge` writes `notes`. The frontend
  route is `/memory`, the nav says Memory, and `frontend/src/pages/Memory.tsx:190`
  reads `export default function Notes()`. The per-scope index file is called
  `MEMORY.md` and contains notes. "Memory" is the right word for the PLACE; "note"
  is the right word for the THING. The code has it backwards at both ends.
- **A second store that is only a delivery mechanism.** 49 rows of "learnings"
  across five JSONL files, about 3,600 tokens, pasted verbatim into the top of
  every chat prompt in scope, invisible to the operator, with no read surface
  anywhere in the app. 11 of the 49 (22%) are machine noise about one finished
  ticket, injected permanently as standing rules.
- **The collector is a function, not an agent.** `learnings.prune_stale`
  (`learnings.py:1103`) has zero callers outside its own CLI. It has never
  archived a row and could not today, since `_AGEOUT_DAYS = 90` and the oldest row
  is 36 days old. `set_pinned` (`:771`) also has zero callers, so no row can ever
  be pinned, and none is.
- **The operator cannot search his own workshop.** `semantic_index.search` has
  zero HTTP routes; its only non-test caller is the MCP server, so it is
  agent-only. The Memory page's search is substring matching over note bodies.

### 1.3 Providers and credentials

`services/model_providers.py` and `services/model_credentials.py` exist, are
correctly reasoned, encode the licensing rule as data, and are imported only by
`llm_router` and each other. Zero HTTP routes. Zero UI. `secrets_crypto.py` is a
working AES-256-GCM envelope encryption that is dormant by default.

Two corrections to assumptions carried into this session:
- `budget_engine.py` and `budget_store.py` are the Plaid personal-finance planner.
  They have nothing to do with AI spend. The AI spend ledger is `usage_ledger.py`,
  and it has no model, provider or currency dimension at all: one project string,
  tokens only, one fixed rolling 5h window.
- Anthropic has never offered an embeddings API and does not now. Its own docs say
  so and point at Voyage AI.

## 2. What a memory is (the decision)

**One store. Notes. A note has a `reach`.**

- `index` (default): the note's title and hook appear in the scope index; the body
  is retrieved on request.
- `always`: the body is injected verbatim into every prompt in scope. This is what
  a "learning" is today, and it is the ONLY thing that made learnings a separate
  system.
- `search`: findable, never surfaced. The archive tier.

Rejected: a `kind` field with `learning` as a value, because it preserves the
unanswerable write-time question of whether a given sentence is a note or a
learning. Two protocol blocks 21 lines apart in `chat_context.py` (`:275` and
`:296`) both say "durable" and both say "scoped", and ask the model to sort on a
distinction neither of them states. It does not work, and 22% machine noise is the
evidence.

Rejected: keeping them separate, because the machinery argument runs backwards.
Notes have working retirement (`enforce_index_cap`) and no dedup. Learnings have
working dedup (17 archived rows prove it) and no retirement. Each has exactly the
half the other lacks.

**Naming.** "Learning" is a gerund used as a count noun that names provenance
rather than function, and every row is in fact an imperative. Call it a **standing
note**, and describe the property as **always in context**. The operator's
objection to the name was correct.

**The fold pays for itself immediately.** The 49 invisible rows become notes on
`/memory`, with titles, edit and delete, through routes that already exist. The
separately-planned "make learnings visible" work is struck, because a note is
already visible. Roughly 1,100 of `learnings.py`'s 1,467 lines are deletable.

WHAT MUST SURVIVE: write-time dedup and supersede; the quality gate that refuses a
bare status token, narrowed to `reach: always` writes; a provenance count; one
`last_used` timestamp in place of four counters; and the injected token budget as
a number the operator can see.

## 3. Finding and surfacing memory (the decision)

The operator named the tension exactly: do not inject a shopping list that induces
pointless retrieval, but do not leave a model unaware that context exists at all.

**Hybrid, and the two halves are asymmetric on purpose.**

- **A corpus map, always, in the cache-stable prefix.** 84 tokens measured. It
  counts distinct SOURCES, not chunks (216 docs, 132 notes, 65 chats, 254 tickets),
  and states that superseded material is demoted rather than hidden. It tells the
  model the shape of the corpus so it knows there is something to look for, and it
  never varies per turn, so it costs no cache.
- **A relevance hint, rarely, past the cache breakpoint.** Titles and scores only,
  never body text, capped at 2, at a floor of **0.85** rather than the 0.65 search
  floor, with the current thread excluded. Measured firing rate 14%, about 9 tokens
  per turn amortised.

THE MEASUREMENT THAT DECIDED THE FLOOR, and it is not in any prior design: 96 of
120 sampled real operator messages return the CURRENT THREAD as their top hit. The
chat corpus contains the conversation the hint would be computed inside. Unfiltered
at the search floor, a hint fires on 100% of messages with a median top score of
0.908. A naive implementation would have produced precisely the shopping list the
operator warned against, on every single turn.

**The failure mode, stated so it is recognisable:** firing rate above 30%, the same
titles under unrelated questions, and the model opening hints without using them.
The operator would see it as chats reading documents before answering questions
that did not need it. If that appears, the hint is wrong and is removed, not tuned.

**Tools: net plus one.** Keep `search`. Add `open_ref(ref, part)`, because `search`
can only ever return 2 chunks of 1,200 chars per document and there is currently no
way to read the rest of a thing you found. Extend the existing `where_is` to carry
the corpus map rather than adding a seventh tool. Reject "more like this": it is
`search` with the passage as the query.

**For the operator:** one route, `GET /api/memory/search`, onto
`semantic_index.search` with NO `from_scope`, because he owns every scope and
passing it engages the share layer. Replace the Memory page's search rather than
repointing it.

## 4. Providers, credentials and limits (the decision)

The operator's direction is recorded verbatim in
`providers-credentials-and-limits-2026-08-23.md` section 1, including the parts
that are unfinished and may change. The load-bearing decisions:

- **Two interfaces**, `LlmProvider` and `EmbeddingProvider`, with a provider record
  carrying `transport` (`cli_subprocess` | `http`) and `wire` (`anthropic_messages`
  | `openai_chat`). OpenAI-compatible `/v1` is the FLOOR, not the universal adapter:
  this platform's turn model is Anthropic-shaped (cache breakpoints, typed thinking
  with `budget_tokens`, `count_tokens`, parsed tool args), none of which is
  expressible over Chat Completions. Ollama, llama.cpp and LM Studio all shipped
  native `/v1/messages` in January 2026, so the Anthropic wire is now a local
  target too.
- **Credentials** stay in `model_credentials`, move under the owner partition, and
  the already-built KEK becomes mandatory at boot in multi-user mode. A key belongs
  to a principal; a project or agent holds a `provider_id` reference, never a copy.
  The UI renders only what `available_providers()` returns, so a prohibited
  subscription provider is ABSENT rather than shown disabled. That is how a user is
  never led toward violating their own Anthropic terms.
- **One resolution order**, extending `routes/chat.py:211`: request, then thread or
  job pin, then agent declaration, then app or project default, then principal
  default, then deployment default.
- **Limits extend `usage_ledger`. There is no second budget system.** Add
  `provider`, `model` and `micro_usd` to the row. Replace the two-knob config with a
  rule list of `{scope_kind, scope_id, window, unit, amount, on_breach}`. All
  matching rules must pass; the most specific is reported first; outcomes are
  refuse, degrade or warn, and nothing queues. Today's reserve-fraction admission
  becomes one `autonomy` rule with identical behaviour. The 2026-08-22 incident
  where chat compaction starved the loop was exactly a cost billed to the wrong
  budget, which is the argument against building a parallel one.
- **Settings**: a `/settings/models` tab. End user sees Models, and Providers and
  keys. Advanced disclosure holds local models and the limits rule table. The cap
  editor moves out of `Usage.tsx`, so intent lives in Settings and measurement lives
  in Usage.

**The cost axis is dead and this simplifies everything.** The entire 12,691-chunk
corpus costs under $5 a year to embed on any hosted provider. So the platform
should never ask a user for an embedding key. Bundle the local embedder, which is
already what ships, and if a hosted provider is ever added, absorb the cost. That
removes embeddings from the business-model question entirely.

The business model itself stays OPEN. It is recorded with its options and their
consequences in section 10 of the providers doc, and two implementation stages are
explicitly blocked on it. Nothing else is.

## 5. What is still wrong

Ordered by consequence.

1. **Four gates carry the inherited-debt defect latently** and will reject an
   innocent run the moment a count drifts: `check_no_process_globals.py`,
   `check_no_state_in_source.py`, `check_no_raw_paths.py`, `check_opaque_fields.py`.
   The general form is section 1.1's principle, and it should be fixed once, in the
   invocation convention, not four more times.
2. **Nine approved commits stranded on locked worktree branches**, and five tickets
   marked `done` whose only implementation sits unmerged. `main` therefore claims
   fixes it does not contain, most pointedly the no-app-names gate fix itself. This
   needs an operator decision on merging, not an autonomous one.
3. **No trigger dispatcher is scheduled.** There is no crontab on this host at all
   and `dispatch_triggers.sh` is not in `infra/cron/workshop.crontab`. Hence
   `trigger-state.json` frozen 36 days and `memory_keeper` frozen the same. Anything
   scheduled must use the backend lifespan reconciler, which the semantic index
   maintenance loop already demonstrates.
4. **Two runners swept one tree** because `work_driver.queue_key` hashes the path
   string and the tree is reachable by two paths, leaving 357 leaked lock files.
5. **The usage ceiling stopped a sweep today** at `development 2051297/1500000` in
   the 5h window. It is doing its job, but it is a single undifferentiated knob, and
   section 4's rule list is its replacement.
6. **`ticket_readiness` rejects every ready ticket** for missing acceptance and
   boundaries, which is the gate asking for what `docs/ticket-writing.md` already
   requires. The backlog needs a pass, not a gate change.
7. **102 of 389 route paths have no caller anywhere**, and `routes/git.py` is 19 of
   20 operations dead.
8. **`skills.py` is an entire module with zero callers**, alongside 226 other
   uncalled public functions.
9. **The note-triager has still never executed once.**
10. **Nothing detects an inert mechanism**, which is the recurring defect itself and
    the reason this list keeps being rediscovered rather than remembered.

## 6. Order of work

The rule for this ordering: nothing that depends on the loop goes before the loop
works, and nothing that depends on being able to SEE a thing goes before there is a
surface for it.

**Stage 0, done today.** The three gates delta-scoped. `reclaim()` reads the live
store. One real ticket driven to `in_review`. The chat ticket count made
chat-specific. Four overlay implementations unified onto the kit primitive.

**Stage 1, connection. No new concepts.**
- The remaining four latent gates, fixed once as a convention.
- `GET /api/memory/search` and the Memory page search replaced.
- `GET/PUT/DELETE /model-providers` plus the Settings section, which makes the
  existing credential store reachable for the first time.
- The corpus map in the fresh-session prefix.

**Stage 2, the fold. Mostly deletion.**
- Notes gain `reach`. The 49 learning rows migrate with a conservation count.
  `learnings.py` and the JSONL store are deleted, not left beside the new thing.
- The naming is corrected: a note is a note, Memory is the place.
- The relevance hint, behind a flag, with its firing rate logged from day one so
  the failure mode in section 3 is detectable rather than arguable.

**Stage 3, providers.**
- Credentials under the owner partition, KEK mandatory in multi-user.
- Ledger dimensions and the price table, then "By model" in Usage.
- The resolver, then a second and third provider. The third is the local HTTP
  provider with a probe, and it is the stage that actually delivers the operator's
  ask of running fully local.

**Stage 4, limits.** The rule list. Build the engine, ship no new default rules,
because the defaults are a business decision.

**Stage 5, the ratchet that detects inertness.** Deliberately last, because it is
the generalisation of every defect above, and generalising before the instances are
fixed produces a checker pinned at a number nobody can act on.
