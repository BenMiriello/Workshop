## 1. The design, in six lines

Settled today, model of record, do not re-litigate:

1. **A thread is the one entity.** Every thread is chattable. `armed` decides
   whether it works unasked; `role` names a definition. Independent fields,
   neither implies the other. "Agent" describes an armed thread, not a second
   object.
2. **A role is `{name, prompt, tools, writes}`.** `writes` stays the closed
   maker/reviewer/triager/keeper/broker enum (it is a permission). `name` is
   free text.
3. **The word is branch.** A branch has exactly one worktree. Worktree is an
   implementation detail and stays out of the interface.
4. **The primary axis is the TICKET.** It is the only object that spans the
   whole life of the work: it exists before a branch does and after the branch
   is merged and deleted. Branches are a *lens*, not a home. Threads do not
   nest under branches; a thread has a *current* branch the way a shell has a
   working directory, and an orchestrating thread has none.
5. **The lease is a queue, not a negotiation.** No agent-to-agent bargaining, no
   "primary thread" setting.
6. **Global Chats stays a flat list, newest first.** Grouping it by branch was
   built and reverted on 2026-08-29. Settled. Do not rebuild it.

The governing rule: **a change deletes the surface it replaces in the same
commit that adds the new one.**

## 4. Chat memory, context and compaction: where it actually stands

Asked directly at the checkpoint, so answered precisely.

**Done.** The memory store is files, path-aware, split `system/`/`user/`. The
semantic index is real and working (local ONNX, ~12.5k chunks) and now covers
every note. Compaction *visibility* is fixed. The learnings store is folded into
notes; only inert files remain on disk.

**Not done, and these are the substance of "fix chat context":**

- `0e810bf9` **Declare every prompt block and its cap in one PROMPT_BLOCKS
  registry.** This is the keystone. Nothing today measures or bounds what goes
  into a turn's prefix.
- `4614bfee` Gate the prefix budget with a check, so it cannot silently grow.
- `c971b8f9` Measure the whole turn-1 window.
- `f8fced4a` Index PROJECT.md and project-root markdown into the corpus.
- `1f0d6dcd` (blocked) Inline only the PROJECT.md brief, with a recency window.

**What is NOT designed yet**, and is the real gap: *what a compaction should
keep*. The current fold is a summariser call. Nothing decides what survives on
principle, and there is no doc for it. That is the next design question in this
area, and it should be answered before more compaction code is written.

## 5. Two systems that were lying, and are fixed

Recorded because both were invisible for a long time and both wasted real hours.

- **The test suite wrote the operator's live jobs feed.** `test_apps_api.py`
  opened a Job on every run; those rows carry no pid, and `reconcile_stuck` will
  not write a pid-less job off for two hours. So the dashboard showed nine runs
  in flight against three real processes, and running the suite kept putting
  fresh phantoms back. Fixed by an autouse fixture, same shape as the one that
  fixed this exact class for the usage ledger on 2026-08-26.
- **Dead code that named a retired store.** An audit read `standing._dir` /
  `_path` (uncalled, and `_dir` re-created the directory as a side effect) plus
  leftover `.jsonl` files and concluded the learnings fold had never happened.
  It had. A ticket was filed to redo finished work. Dead code naming a retired
  thing is a false claim the next reader must disprove.

The general lesson from both: **when a gate or a doc disagrees with the tree,
measure the tree.**
