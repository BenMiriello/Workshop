# Audit, 2026-08-31: what is broken, measured against the running system

Method: not a read of the plan. Every claim below was checked against the live
backend on :8000 and the built bundle on :8002 — 159 parameterless GET
endpoints swept, 39 routes loaded in a real browser with console and network
capture, the full backend suite run to completion, and the screens read as
PNGs.

The headline is that the plan documents were not the problem. The code matched
the design in almost every place I looked. What was wrong was the seam between
backend and frontend, and nothing in the repo was watching it.

---

## 1. The finding that mattered: a silent contract rename

`GET /api/tasks` and `GET /api/jobs` moved to `Page[T]` on **2026-08-17**
(`7e4aacbf`): `tasks`/`jobs` became `items`, and `total` moved inside `page`.
The route's own docstring records the rename as a deliberate supersession.

**Seven frontend call sites were never moved with it.** Each hand-wrote its own
response type, so each still typechecked while reading `undefined` at runtime:

| surface | read | showed |
|---|---|---|
| `/tickets` table | `data.tasks` | "No tickets yet" over **188 active tickets** |
| `/tickets` board | `j.tasks` | empty lanes |
| `/runs` feed | `data.jobs` | empty feed |
| run detail | `.jobs` | a run's child runs never appeared |
| `/agents` | `.jobs` | no last run on any row |
| project detail | `d.tasks` | no task list |
| chat work panel | `.tasks` | nothing |

Two weeks. No error anywhere, because **an empty list is what a missing key
looks like**. The dashboard's `fetchRunning` had been migrated correctly, which
is why the home screen looked healthy throughout.

Fixed in `17a6ad96`. The two ticket surfaces now name
`components["schemas"]["Page_Task_"]` from `schema.gen.ts`, which is generated
from the routes and gated by `check_generated_client.py` — so the next rename
is a red typecheck, not a blank page.

### The lesson, which is structural

`frontend/CLAUDE.md` already says to prefer the generated types and records
that ~528 hand-written response types remain. This is what that debt costs when
it comes due. **The remaining hand-written types are the largest known source
of silent breakage in the tree**, and they fail invisibly by construction.

## 2. The backend suite has been unrunnable, so nothing gated on it

`pytest tests/` stopped at 32% and hung. Cause: `test_compact_detaches.py`
called the real `compact_thread`, which since `5be52599` sends `/compact` as a
turn and spawns a CLI that never returns under pytest. Five of its six tests
also asserted a `session_reset` key the response no longer has.

Both were my own breakage from the compaction change, left behind when the fold
was deleted.

Rewritten as `test_compact_uses_the_provider.py` against a stubbed `_send`
(`2344bbde`). **The suite now completes for the first time:**

```
4030 passed, 23 failed, 102 errors, 3m18s
```

- The **102 errors** are all `WORKSHOP_DATABASE_ADMIN_URL` being absent in this
  sandbox. They are environmental and would pass on the host.
- The **23 failures** are real debt, and are now countable — they were not this
  morning. Listed in §6.

`scripts/reviewer.sh` still runs mypy and never pytest. That was defensible
while the suite could not finish. It is not any more.

## 3. The app tabs listed things that do not exist, and withheld things that do

Both mine, from `a36a30cc`, and both reported by the operator before I found
them.

**59 of 126 chats on one app were unopenable.** I merged the DB's app link onto
the file fold and kept rows the fold did not have, "thin, rather than vanishing
from its app". Measured: those rows carried the backfill's own timestamp, no
title (rendered "New chat"), no messages, and `GET /chat/threads/<id>`
answering **404**. Across the install: **62 phantom rows, 59 on the platform's
own app, 3 on another** — so it was never one app's problem.

The fold is the store that can actually serve a thread, so it decides what
exists. The DB still decides *which app* a chat belongs to, which is the part it
is authoritative for. 126 → 67 rows, none thin.

**The tickets tab showed none of 409 tickets.** Over `MAX_ROWS` the shared
collection body returned a region reading "Too many to render" and rendered
nothing, hinting that the operator should go close tickets out. A long list is
not an error; rule 9 says overflow is paginated or scrolled, never withheld.

Fixed in `491cbb77`.

## 4. The tree was collecting junk directories

Eleven directories at the repo root named after **ticket ids**, each holding an
empty task store. `_locked()` creates its root, so any caller passing a relative
path made a directory under the process cwd.

They were invisible to `git status`: `.gitignore` had been widened to catch
`.tasks.json`/`TODO.md` at any depth, and an untracked directory whose every
file is ignored is not reported. The comment added with that widening noted
"four more such directories are on disk right now". Four days later there were
eleven, and they were rendering as top-level folders in the Files tree of the
platform's own source. One had previously been committed (`379d82fa`).

A task-store root must now be absolute (`8d9b4cb6`). A ticket id is not a
scope, so no correct caller can arrive with one. 113 task tests pass unchanged.

## 5. Smaller things found by looking at the screens

- **The board printed raw priority integers** (`80`) where the table printed
  bands (`high`). `lib/priority.ts` exists precisely to stop this and its header
  records the day five agents filed carefully graded numbers and every
  distinction collapsed. The board never converted. (`49bb67b5`)
- **"Search 0 tickets" over a board of 176.** The page-level query is disabled
  in board view, so 0 was not a count, it was the absence of one. (`49bb67b5`)
- **A permanently-disabled "Timeline" view** advertised a feature that does not
  exist and could not be dated. Deleted. (`7ebaea04`)
- **The platform's own app sorted last in the dock**, under every app built with
  it, because a spec-less app row is appended after every catalog app. Now first,
  by the `self: true` declaration rather than by name. (`2344bbde`)
- **`lib/activeTickets.ts` was dead** — the work drawer moved to
  `GET /chat/threads/{id}/work` and only its own test still referenced it. It
  also read the pre-rename shape. Deleted. (`17a6ad96`)

### What was checked and found correct

Worth recording, so it is not re-audited: no console errors, no failed requests
and no blank pages on any of 39 routes; no 500s across 117 live endpoints; the
`/memory` and Files pages are directory pages and their small `main` is correct,
not an empty state; the app nav column is collapsed by default **by design**
(an app owns its width) and the dock tile toggles it correctly — all eight rows
present and linking correctly.

## 6. What is still broken

### The 23 real test failures

```
test_chat_turn_lifecycle  1   test_next_ready_unattended       4
test_db_schema            1   test_runner_brake_split          1
test_db_tenancy           1   test_scoped_exec                 2
test_dev_mode_gate        3   test_semantic_index              1
test_doc_status           1   test_ticket_producers_state_...  2
test_edge_websocket_proxy 1   test_memory_consolidation_m6     3
```

Three clusters are worth naming: `test_dev_mode_gate` (3) and
`test_runner_brake_split` (1) are the ADR-0014 interlock and matter most;
`test_next_ready_unattended` (4) is the scheduler that picks autonomous work;
`test_memory_consolidation_m6` (3) asserts the content of specific notes and may
simply be stale.

### Known and unbuilt

- **Uploaded images survive exactly one turn** (`build_streaming.py:2666` reads
  per-message attachments). Zero of 409 tickets cover it. The operator asked for
  this on 2026-08-27 and called it the most costly unbuilt item.
- **Two unlinked registries** (`.runtime/projects.json`,
  `.runtime/installed-apps.json`), five slugs in both. `app-is-the-entity` §9
  migration is not built.
- **`/projects` and `ProjectDetail`** (2,025 lines) are still the only UI for
  autonomy, deploys and environment. They go when the Work view absorbs those
  panels, not before.
- Handoff dependency order, still unbuilt: `d5a051c8` thread `armed`+`role`
  (keystone), `9fc4ce67` Roles page, `130ef15e` Work view, `427a86fe` Branches
  lens, `d12a0332` delete `/projects`, `85a51a32` Settings 12→9.

## 7. What to do next, in order

**1. Wire pytest into `reviewer.sh`, pinned at the current failure set.**
The suite finishes now, so the reason not to is gone. Pin the 23 as a ratchet
that may only go down, exactly like `check_no_app_names`. Without this the next
contract rename breaks something else for two weeks. *Cheapest high-value item
on this list.*

**2. Convert the remaining hand-written response types, endpoint by endpoint.**
§1 is not a bug that was fixed, it is a bug class with ~528 instances. Prioritise
every list surface: those are the ones that fail as "empty" rather than as an
error. A route with no `response_model=` has no generated type, so this is
partly backend work (`check_response_model.py` tracks that debt).

**3. Fix the ADR-0014 interlock failures** (`test_dev_mode_gate` ×3,
`test_runner_brake_split` ×1). This is the gate deciding what may run against
the platform's own source. It should not be the thing with red tests.

**4. Context persistence for uploads.** Oldest unaddressed operator request,
and it has a measured cost (a 5.5-hour mockup loop).

**5. Then, and only then, the unbuilt feature order** from the handoff, starting
with the `armed`+`role` keystone.

The ordering principle: **items 1 and 2 are what stop this audit from being
needed again.** Everything below them is feature work that will break silently
in the same way until the seam is watched.
