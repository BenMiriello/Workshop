4a Built on the real transcript
An assistant turn is one bubble. AssistantTurn splits its segments at the last run of text: everything before is work (chat-work), everything after is the answer. Both live inside the same chat-bubble, work above answer, with one toggle at the top of the bubble — that is the only thing that collapses a turn's steps, and it never touches the answer. So a ticket card, which is a ui-card in the answer text, cannot be hidden by folding steps.
Three disclosure levels already exist and each keeps its scope: the work block (top of bubble), one item inside it (each tool chip and subagent chip opens itself), one message's length (Show more at the bottom). The ticket card is a fourth thing — an item in the answer — and it opens itself, like a chip does.
Everything on the card is a real field: status, depends_on, awaiting, labels, and from the run: duration, and the receipt's files-changed and commits. No invented progress. Buttons are the ones that exist — View job → /runs/{id}, Open ticket → /tickets/{scope}/{id}.
Five states: resting · steps open · card open · another agent asking · answering in the Work panel. Desktop last.

3a Grounded in the real model
Three entities, three destinations, and one rule about where each is answered.
Ticket (a task: scope + id, eight statuses, depends_on, awaiting, job_ids) → /tickets/{scope}/{id}. Run (a job: status, duration, receipt) → /runs/{id}. Agent (who is executing) → /agents/{slug}. A ticket has many runs over time; the card shows only the current one, and that run names one agent.
The in-chat card is a ui-card inside the assistant's own bubble — the same place proposals already render — so it sits in the answer, not in the work section. Collapsing the work steps never hides it. It is itself collapsible: one line resting, its detail on tap.
Answering. If this chat is running the work, the agent asks here, in the thread, as it already does. If another agent is running it, the question belongs to the ticket and is answered in the Work panel — options or free text. The in-chat card only carries a notice that one is waiting.
Six states, left to right: resting · card expanded · work steps folded · question waiting · Work panel · answering in the panel. Desktop after.
